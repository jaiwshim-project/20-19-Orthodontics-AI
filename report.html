1. 경영·개발 요약

플랫폼은 환자 자료 수집부터 Class 분류, EZ/TZ 분석, 발치 판단과 치료계획으로 이어지는 MVP 흐름을 갖췄습니다. 다만 “작동하는 기능”과 “임상적으로 검증된 모델”은 구분해야 합니다.

● 13개 입력 UI 완료 ● Class I·II·III 출력 완료 ● 로컬·Supabase 저장 흐름 ● EZ/TZ 자동 초안·수동보정 ● KRR 연구 모델 ● 환자 상담 AI(Claude·RAG) 배포 ● 외부 임상 검증 미완료

완성된 것

화면·저장·AI API 호출·결과 렌더링·재학습 하네스·중첩 검증·수동 보정 순환까지 구현됐습니다.

검증된 것

EZ/TZ 규칙 엔진과 KRR 좌표 개선은 수치 검증됐습니다. Class 분류 API 소스는 구문 검사에 통과했습니다.

아직 증명되지 않은 것

Class I·II·III 독립 정확도, 13개 전체 입력의 진단 기여도, 신규 환자에서의 임상적 일반화는 아직 확정할 근거가 없습니다.

현재 상태를 한 문장으로 표현하면 “13개 자료를 수집하는 교정 AI 플랫폼과 3장 핵심 영상 기반 Class 분류 기능은 개발 완료됐고, EZ/TZ 자동분석은 연구 모델까지 진전됐지만, 임상 배포 정확도는 추가 정답 데이터와 잠금 테스트로 확정해야 하는 단계”입니다.
2026-07-19 갱신 KRR 보정으로 규칙 엔진 대비 정확도가 크게 향상됐습니다(치아 폭 41%↓, EZ 곡선 60%↓, TZL 45%↓, EZL 37%↓). 5-fold 중첩검증은 10개 게이트 중 9개를 통과했고 승격을 막는 것은 TZL P95 꼬리 오차 하나뿐입니다. 남은 병목인 구치부(어금니) 정밀도를 높이기 위해, 오늘 확보한 교정 후 하악 사진 114장에 치아 폭 정답을 라벨링해 학습 데이터를 배가할 예정입니다. 운영 규칙 엔진 HTML은 변경하지 않았습니다(SHA 불변).
2026-07-20 갱신 — 환자 상담 AI(RAG) 신규 배포 김용을 원장의 EZL/TTL 이론 자료를 Supabase 지식베이스(knowledge_chunks, pgvector)에 저장해 환자에게 쉬운 언어로 설명하는 환자 상담 AI를 신규 개발·프로덕션 배포했습니다. 대화는 Claude(claude-opus-4-8)가 생성하며, 답변마다 참조한 원장 자료를 출처로 표기합니다. RAG 검색은 벡터 검색을 우선 사용하되, 임베딩 제공자 장애 시 키워드 검색으로 자동 폴백해 무중단 동작하도록 설계했습니다. 환자 이름 등 개인 식별 정보는 답변·컨텍스트에서 제외합니다.

4. Class I·II·III 분류 알고리즘

현재 Class 분류는 자체 학습된 13장 융합 신경망이 아니라, 핵심 3장을 범용 멀티모달 AI에 전달하고 교정학 기준 프롬프트와 후처리 규칙으로 판정하는 구조입니다.

실제 입력

측면 세팔로로 골격 Class 경향을 보고, 좌·우 구강 측면으로 구치·견치 관계와 교차교합을 확인합니다.

AI 공급자

Anthropic이 설정되면 우선 사용하고, 다음으로 Azure OpenAI Vision, 마지막으로 Gemini 2.5 Flash를 사용합니다.

오진 방지 규칙

총생으로 인한 전치 돌출을 Class II로 오인하지 않도록, Class II는 골격 근거와 구치·견치 관계를 함께 요구합니다.

출력

Angle Class, 골격 경향, dental findings, cephalometric impression, 치료 접근, 위험요인과 제한점을 JSON으로 반환합니다.

신뢰도 후처리

  • AI가 제시한 confidence는 0~0.95로 제한합니다.
  • 증거 문장 수, 세팔로 근거, 좌우 양측 근거에 따라 최소 신뢰도를 조정합니다.
  • 좌·우 중 한쪽 근거가 없으면 0.70 이하로 제한합니다.
  • Indeterminate 결과는 낮은 신뢰도로 제한합니다.
정확도에 대한 현재 결론 폴더에서 Class I/II/III confusion matrix, 독립 테스트 정확도, 민감도·특이도, macro-F1 보고서는 확인되지 않았습니다. 따라서 화면에 표시되는 confidence는 임상 정답으로 보정된 확률이 아니라 규칙 기반 표시값이며, “Class 분류 기능 개발 완료”는 맞지만 “임상 정확도 검증 완료”로 표현하면 안 됩니다.
13장 융합과 3장 분류의 차이 api/comprehensive-diagnosis.js는 구강 5장·안면·세팔로·EZ/TZ를 종합할 수 있도록 작성됐지만, 현재 어떤 화면에서도 직접 호출되지 않습니다. 실제 classification.html은 api/classify-diagnosis.js만 호출하며 3장만 전송합니다.

치아 크기 알고리즘의 핵심 문제

  • 규칙 엔진이 대칭 포물선 악궁을 12등분하므로 실제 구치부 비대칭과 회전을 충분히 반영하지 못합니다.
  • 평균 5% 폭 과소평가는 1.051배 보정으로 줄였지만, 잘못된 측정선 위치는 그대로 남습니다.
  • KRR은 규칙 엔진의 잔차를 보정하는 방식이라, 규칙 엔진의 구치부 예측 자체가 나쁘면(5%대) 보정 후에도 상한이 걸립니다.
  • 경계 정렬, 법선 탐색, 어금니 탐색 확대는 이미 시험했으나 개선되지 않아 데이터 확대와 재학습이 우선입니다.
  • 어금니 오차 상위 20건을 molar_correction_targets.json으로 목록화했습니다. 다만 기존 정답이 이미 학습에 포함돼 있어, 재라벨보다 신규 정답 이미지 추가가 근본적으로 더 효과적입니다.

9. 정확도 향상을 위해 필요한 자료

Class I·II·III 분류

최소 파일럿

Class별 100명 이상, 총 300명 수준의 균형 자료를 권장합니다. 각 Class에서 최소 20~30명은 잠금 테스트로 처음부터 분리해야 합니다.

임상 일반화 검증

병원·촬영장비·연령을 달리한 Class별 200명 이상, 총 600명 이상의 다기관 자료가 더 안정적입니다.

  • 동일 환자의 13개 자료가 정확히 연결된 비식별 케이스 패키지
  • 전문의 2인 이상 합의 Class, skeletal Class와 dental Angle Class 분리 라벨
  • Class II Division 1/2, subdivision, borderline, asymmetric, indeterminate 라벨
  • ANB/Wits와 주요 세팔로 랜드마크 정답, 좌·우 구치·견치 관계 정답
  • 촬영 장비·각도·화질·결손·보철·성장단계와 익명 patientGroupId
  • 초진·최종 자료는 같은 환자가 train/test로 갈라지지 않도록 환자 단위 분리

EZ/TZ와 치아 크기 분석

진행 중 (2026-07-19) 오늘 확보한 교정 후 하악 사진 114장에 치아 폭 정답을 라벨링해 제공할 예정입니다. 교정 후 치열은 어금니까지 이상적으로 정렬돼 있어 구치부 라벨 품질이 높고, 기존 교정 전 정답과 이미지가 다른 완전 신규 케이스라 학습 데이터가 113 → 227건으로 배가됩니다. 받는 즉시 이미지 SHA·좌표·스케일 무결성 검사 → 20장 잠금 테스트 분리 → 재학습 → 어금니·TZL P95 재측정 순으로 진행합니다.
  • 교정 후 치아 폭 정답 114장: 신규 폴더 저장, 파일번호 접두어 유지, imageData·toothWidths 12개·molarMm 54 포함(보정 후 HTML의 위치 저장 형식). 교정 전 정답과 폴더 분리.
  • 이 중 최소 30건은 1·2·11·12번 구치부 오차가 크거나 비대칭·회전이 있는 사례를 우선 확인·보정
  • 10건 정도의 반복 라벨과 제2 전문가 독립 라벨로 정답 변동성 측정
  • 운영 안정화 목표라면 여기서 다시 다양한 형태(V형·비대칭·총생)로 추가 확대
