## 1. 프로젝트 목적

새로운 환자의 **하악 교합면 사진**을 업로드하면 다음 항목을 자동으로 분석하는 단일 HTML 프로그램을 개발한다.

1. 각 치아의 좌우폭 측정선과 길이
2. 전체 치아 폭 길이 합계인 `TZL`
3. 환자별 치조골/구강 형태에 맞춘 EZ(Equilibrium Zone) 중심점과 곡선
4. EZ 곡선의 전체 길이인 `EZL`
5. `EZL - TZL` 차이

이 결과는 공간 부족량을 이해하고 발치 또는 치간 삭제(IPR) 여부를 판단하는 데 도움을 주기 위한 **교정 진료 보조 자료**다. 자동 결과만으로 진단하거나 치료 결정을 내려서는 안 되며, 최종 판단은 치과의사가 임상 정보와 함께 내려야 한다.

### 용어 정리

- `TZL`: Tooth Zone/Tooth Width Length로 대화에서 사용한 전체 치아 좌우폭 합계. 초기 대화에서 `TTL` 또는 “총 치아 길이”라고도 표현되었으나, 현재 UI와 문서에서는 `TZL`로 통일한다.
- `EZL`: EZ 곡선의 총 길이.
- 치아 폭: 치아별 좌우 경계점 `p1`, `p2` 사이의 거리.
- EZ 점: 치조골/치열 중심을 따라 전문가가 지정한 점.

개념적으로 계산은 다음과 같다.

```text
치아 i의 폭(mm) = distance(p1_i, p2_i) × 현재 스케일(mm/px)
TZL(mm) = 모든 대상 치아 폭의 합
EZL(mm) = EZ 중심점들을 잇는 곡선의 호 길이 × 현재 스케일(mm/px)
차이(mm) = EZL - TZL
```

실제 계산 시에는 운영 HTML에 구현된 스케일 및 곡선 길이 계산 루틴을 기준으로 한다.

## 7. 실제로 개발한 학습 모델

### 구조

- 규칙 엔진의 결과를 완전히 대체하지 않고, 그 좌표 오차를 보정하는 **잔차 학습 모델**을 개발했다.
- 알고리즘: NumPy 기반 RBF Kernel Ridge Regression(KRR).
- 입력: 규칙 엔진이 생성한 정규화 기하 특성 169개.
- 치아 폭 출력: 12개 폭선의 양 끝점, 총 48개 좌표.
- EZ 출력: 12개 EZ 점, 총 24개 좌표.
- 치아 폭 모델과 EZ 모델은 분리 학습했다.
- 모델 JSON 크기: 약 1.1MB.
- 새로운 형태가 학습 분포와 너무 다르면 규칙 엔진으로 되돌아가는 fallback과 보정량 상한을 설계했다.

### JavaScript/Python 추론 일치 검증

- 검증 사례: 13건.
- task 평가: 78회.
- 비교 숫자: 12,974개.
- 최대 절대 차이: `7.0486e-12`.
- 허용 오차: `1e-9`.
- legacy, pixel-diagonal, deployment-policy 모드 모두 일치했다.

즉, 모델 수학을 브라우저 JavaScript로 옮기는 과정의 수치 오차는 사실상 없다. 현재 문제는 구현 번역이 아니라 데이터 일반화와 임상 길이 오차다.

배포 거부 정책은 fail-closed다. 거부된 후보를 재생하려면 명시적으로 `allowResearchPolicy: true`를 지정해야 하며, 운영 HTML에서는 사용하지 않는다.

## 8. 재학습 실험 결과와 정확도 해석

### 8.1 1차 좌표 교차검증

처음의 KRR 좌표 검증에서는 다음과 같은 개선이 관찰되었다.

| 항목 | 기준 MAE | 보정 MAE | 평균 개선 | 개선 fold |
|---|---:|---:|---:|---:|
| 치아 폭 좌표 | 0.03807 | 0.02964 | 22.15% | 5/5 |
| EZ 좌표 | 0.04269 | 0.02656 | 37.77% | 5/5 |

그러나 좌표 평균만 좋아졌고, TZL/EZL 길이의 꼬리 오차 및 일부 사례의 악화가 있어 이 결과만으로 배포하지 않았다.

### 8.2 2차 후처리 정책 후보

- 실제 이미지 대각선 기준 보정 상한: 5%.
- 치아 폭 blend: 0.32, gate: 0.90.
- EZ blend: 0.42, gate: 0.73.

같은 OOF 결과에서 선택한 연구용 지표는 다음과 같았다.

- 치아 폭 좌표 개선: 약 12.68%.
- EZ 좌표 개선: 약 12.70%.
- EZL MAE 개선: 5.43%.
- TZL MAE 개선: 4.07%.
- 차이값 MAE 개선: 8.47%.

하지만 이 정책은 같은 결과를 보고 선택되었으므로 선택 편향 가능성이 있었다. 따라서 최종 배포 근거로 사용하지 않고, 더 엄격한 중첩 검증을 수행했다.

### 8.3 권위 있는 누수 방지 중첩 검증

평가 설계:

- 공통 외부 5-fold.
- 각 외부 train 내부에서만 4-fold로 KRR 하이퍼파라미터와 적용 정책을 선택.
- 외부 validation은 선택에 전혀 사용하지 않음.
- 엄격한 내부 기준을 통과하지 못하면 해당 외부 fold에서 규칙 엔진을 그대로 사용.

최종 결과:

| 항목 | 규칙 기준 | 중첩 정책 | 변화 | 판정 핵심 |
|---|---:|---:|---:|---|
| 치아 폭 좌표 MAE | 0.038074 | 0.034852 | 8.46% 개선 | 3/5 fold만 개선, 10% 기준 미달 |
| EZ 좌표 MAE | 0.042688 | 0.037875 | 11.27% 개선 | 3/5 fold만 개선 |
| EZL MAE | 4.753mm | 4.660mm | 1.97% 개선 | P95가 0.691mm 악화 |
| TZL MAE | 4.599mm | 4.743mm | 3.13% 악화 | 평균도 악화 |
| 차이값 MAE | 4.642mm | 4.482mm | 3.45% 개선 | P95가 1.101mm 악화 |

- 엄격한 내부 정책은 외부 5-fold 중 3개에서만 선택되었고, 2개는 규칙 기준으로 fallback했다.
- 임상 길이 MAE 개선에 대한 bootstrap 신뢰구간은 0을 포함했다.
- 즉, 개선이 우연이 아니라고 말할 충분한 증거가 없었다.
- 평균 좌표 오차 일부는 줄었지만, TZL이 악화되고 임상적으로 중요한 P95 꼬리 오차도 나빠졌다.

### 최종 정확도 결론

“정확도가 크게 개선되어 운영에 투입 가능하다”고 말할 수 없다. 누수 없는 최종 검증 기준으로는:

- 좌표 평균은 일부 개선되었다.
- EZL 평균 오차는 소폭 개선되었다.
- TZL 평균 오차는 오히려 악화되었다.
- 최악 구간(P95)은 EZL과 차이값에서 악화되었다.
- 현재 데이터만으로 안정적 일반화가 확인되지 않았다.

따라서 최종 결정은 다음과 같다.

```text
production decision = do_not_promote_research_only
policy status = candidate_rejected_nested_validation
```

운영 HTML에 모델을 적용하지 않은 것은 미완료가 아니라, 부정확한 모델을 임상 보조 화면에 노출하지 않기 위한 의도적인 안전 결정이다.

## 9. 반복학습 3~5회에 대한 결론

정답이 동일한 상태에서 같은 데이터를 단순히 3~5회 다시 학습한다고 정확도가 계속 올라가지는 않는다. 훈련 데이터 점수만 좋아지고 새로운 환자 성능은 나빠지는 과적합이 생길 수 있다.

효과적인 반복은 다음 구조여야 한다.

1. 규칙 엔진으로 전체 사례를 예측한다.
2. 전문가 정답 좌표와 자동 좌표의 잔차를 계산한다.
3. 사례별/치아별/곡선 구간별 오류 패턴을 분류한다.
4. train 데이터에서만 모델과 정책을 조정한다.
5. 보지 않은 validation/test에서 평가한다.
6. 평균 MAE뿐 아니라 P95, 실패율, 임상 길이 오차, 좌우/순서 위반을 확인한다.
7. 개선이 독립 평가에서도 반복될 때만 다음 버전으로 승격한다.

따라서 “3~5회”는 고정된 횟수가 아니라, **새 정보 추가 → 독립 검증 → 실패 원인 교정**의 순환 횟수여야 한다.

## 10. 전문가 개입과 자동 정답 비교의 역할

이미 정확한 좌표 정답이 폴더에 있으므로, 학습 손실 계산은 전문가가 AI 결과를 매번 다시 그리는 것보다 MD/JSON의 좌표 정답과 자동 결과를 직접 비교하는 것이 더 일관되고 빠르다.

하지만 사람의 역할이 완전히 사라지는 것은 아니다.

- 정답 파일이 실제로 올바른 이미지에 연결되었는지 확인.
- 누락 치아, 보철, 심한 회전/중첩, 화질 불량 같은 예외를 표시.
- 전문가 간 기준이 다른 사례를 합의 또는 변동성 데이터로 구분.
- AI의 신규 실패 유형이 기존 정답 정의의 모호성인지 확인.
- 최종 배포 전 임상적으로 의미 있는 오차인지 판정.

권장 방식은 **좌표 기반 자동 비교 + 불확실/이상 사례만 전문가가 검토하는 human-in-the-loop**다.

## 11. 신규 동일 이미지 복합 정답 50건 계획

사용자는 신규 50건을 제공하기로 했으며, 각 사례는 **정확히 동일한 하악 이미지 한 장**에 다음 두 정답을 모두 포함해야 한다.

1. 치아 번호별 좌우폭 측정선.
2. EZ 중심점과 EZ 곡선.

이 방식은 치아 폭과 EZ 위치의 상관관계, 동일 스케일에서의 TZL/EZL, 그리고 `EZL - TZL`을 직접 학습·평가할 수 있어 기존 분리 사진보다 훨씬 가치가 높다.

### 권장 저장 폴더

`C:\01 클로드코드\20-19 Orthodontics AI\00 EZ Curce - TZ Length\04 동일사진 복합정답 50`

### 권장 파일명

```text
001.md
002.md
...
050.md
```

번호는 환자 실명이나 병록번호가 아닌 익명 연구용 case ID를 권장한다.

### 각 정답 파일에 필요한 내용

- 원본과 정확히 같은 `imageData` 또는 검증 가능한 이미지 SHA-256.
- 원본 이미지 너비와 높이.
- `toothWidths`: 치아 번호 1~12와 각 `p1`, `p2` 좌표.
- `ezPoints`: 전문가가 찍은 EZ 점 전체.
- 스케일 기준과 `molarMm` 등 계산에 필요한 값.
- 누락 치아, 보철, 측정 불가, 사진 품질 문제 등의 flags.
- 작업자/버전/저장 시각 같은 provenance.

가능하면 두 결과를 별도 파일로 나누지 말고 한 MD/JSON에 저장한다. 별도 파일이 불가피하면 두 파일 모두 동일한 이미지 해시와 동일 좌표계임을 기록한다.

### 절대 지켜야 할 제작 규칙

1. 두 정답을 찍는 중간에 이미지를 크롭, 회전, 확대/축소, 리사이즈 또는 재압축하지 않는다.
2. AI 자동 결과를 정답으로 복사하지 않는다. 전문가가 원본 사진을 보고 직접 찍은 좌표만 정답으로 사용한다.
3. 치아 번호 방향과 순서를 모든 사례에서 동일하게 유지한다.
4. 불명확한 치아를 임의 추정하지 말고 예외 flag를 남긴다.
5. 가능한 한 촬영 조건과 스케일 기준을 통일한다.
6. 사진과 파일에는 환자 식별 정보를 포함하지 않거나 사전에 비식별화한다.

### 50건의 권장 사용법

- 기존 동일 이미지 복합 정답 52건 + 신규 30건: 학습/검증 풀, 총 82건.
- 신규 20건: 잠금 독립 테스트 세트.
- 잠금 테스트 20건은 모델·gate·blend·상한을 선택하는 동안 열어보지 않는다.
- 신규 50건 중 5~10건은 일정 시간이 지난 뒤 전문가가 이전 표시를 보지 않고 다시 작업하여 intra-rater 변동성을 측정한다.
- 가능하면 일부는 두 번째 전문가도 독립 표기하여 inter-rater 변동성을 측정한다.

신규 50건은 최소 실용 단위로 적절하다. 더 안정적인 하위 유형별 성능과 배포 판단을 위해서는 이후 80~100건 이상의 다양한 신규 복합 정답으로 확대하는 것이 좋다.

### 다양성 권장

신규 50건에는 가능하면 다음 유형을 고르게 포함한다.

- 정상에 가까운 U형 치열.
- 좁고 긴 V형 치열.
- 좌우 비대칭.
- 총생과 회전이 심한 전치.
- 소구치/대구치 경계가 불명확한 사례.
- 보철 또는 결손이 있는 사례(별도 flag 필수).
- 밝기, 색조, 촬영 각도와 확대율이 다른 사례.
- 쉬운 사례뿐 아니라 현재 자동 엔진이 실패하는 사례.

## 12. 다음 재학습의 권장 평가 기준

새 50건을 받은 뒤에는 현재 모델을 무조건 덧학습하지 말고 먼저 데이터 무결성을 검사한다.

### 데이터 검사

- 이미지 해시 중복과 train/test 중복 확인.
- 이미지 크기와 좌표 범위 확인.
- 치아 번호 순서 및 좌우 방향 확인.
- 치아 폭선 개수와 누락 flag 일치 확인.
- EZ 점 개수와 곡선 순서 확인.
- 동일 사례의 치아 폭/EZ가 정확히 같은 이미지 좌표계인지 확인.
- 비정상 길이, 교차선, 역순 점 및 캔버스 밖 좌표 탐지.

### 모델 평가

- 치아 폭 끝점/선분 오차.
- 치아별 폭 MAE(mm).
- TZL MAE와 bias(mm).
- EZ 곡선 symmetric distance.
- EZL MAE와 bias(mm).
- `EZL - TZL` MAE와 임상 허용 구간 정확도.
- 평균, median, P90, P95, 최악 사례.
- 사진 형태/화질/총생 등 하위 그룹별 성능.
- 모델 보정 적용률과 fallback 실패율.

### 배포 원칙

- train 성능이 아니라 잠금 테스트 성능으로 결정한다.
- 평균 개선뿐 아니라 P95가 악화되지 않아야 한다.
- TZL, EZL, 차이값을 모두 확인한다.
- 좌표 개선이 길이 개선으로 이어지지 않으면 배포하지 않는다.
- 임상적으로 허용할 수 없는 최악 오차 사례를 별도 검토한다.
- 기준을 통과해도 자동 결과는 “초안”으로 표시하고 사용자가 수정할 수 있어야 한다.
- 모델 버전, 데이터 버전, 해시, 평가 지표 및 rollback 파일을 함께 보존한다.

## 13. 자동 검증 하네스 상태

재학습 패키지에는 다음 6단계 하네스가 있다.

1. Curator — 데이터와 매핑 검사.
2. Miner — 기준 예측과 잔차 분석.
3. Architect — 모델/정책 후보 구성.
4. Trainer — 학습 및 추론 패키징.
5. Critic — 누수 방지 검증, 임상 지표와 꼬리 오차 평가.
6. Promoter — 기준 통과 시에만 운영 승격.

최종 실행은 `--round 2 --dry-run`이었다. 파이프라인 자체 검증은 PASS였지만 운영 승격은 BLOCKED였다.

차단 사유:

```text
candidate_rejected_nested_validation
nested_policy_failed
clinical_tail_regression
patient_level_grouping_unavailable
deployment_policy_not_authorized
```

여기서 `patient_level_grouping_unavailable`은 현재 데이터에 신뢰할 수 있는 익명 환자 그룹 ID가 없어 같은 환자의 여러 사진이 train/test에 분리되는 것을 완전히 통제할 수 없다는 뜻이다. 새 데이터에는 익명 patientGroupId를 추가하면 좋다.

### 신규 50건이 준비된 뒤 실행할 순서

## 18. 분석 엔진의 실제 저장 위치 확인

### 사용자 질문

### 코드 확인 결과

- 프로젝트 루트에는 별도의 `index.html` 파일이 없다.
- 운영 파일 `EZ Curve - TZ Length.html`에는 현재 규칙 기반 자동 분석 엔진 `tzl-ezl-rule-v1.0`과 `runAutoEngine()`이 포함되어 있다.
- 전문가 정답으로 학습한 연구용 잔차 보정 엔진은 운영 HTML 또는 어떤 `index` 파일에 합쳐져 있지 않다.
- 학습 엔진은 `03 AI 재학습` 폴더에서 다음 파일로 나뉘어 보존되어 있다.

  - `residual-model.json`: 학습된 KRR 모델 파라미터.

- `dataset-index.json`은 이미지와 전문가 정답의 매칭 및 데이터 인덱스이며, 실행 가능한 분석 엔진이 아니다.
- 따라서 현재 운영 HTML에서 `치아 자동 분석`을 실행하면 학습 모델이 아니라 기존 규칙 기반 엔진이 작동한다.
- 연구 모델을 운영 HTML에 포함하지 않은 이유는 권위 있는 중첩 독립검증에서 `candidate_rejected_nested_validation` 및 `do_not_promote_research_only` 판정을 받았기 때문이다.
- 신규 동일 이미지 복합 정답 50건으로 재학습한 뒤 잠금 테스트와 임상 길이/P95 검증을 통과하면, 그때 `residual_inference.js`와 승인된 모델 데이터를 단일 운영 HTML에 내장하는 순서로 진행한다.
