# 어금니 정확도 향상을 위한 라벨링 가이드

- 작성일: 2026-07-21
- 목적: 어금니(치아 1·2·11·12번) 폭 예측의 **랜덤 분산(SD 9~12%)**을 낮추기 위한 신규 정답 데이터 제작 규격
- 근거: P95 꼬리 원인 = 어금니 폭 예측 분산(데이터 부족). 편향은 이미 KRR로 ±2% 해결. 분산은 **표본 수를 늘려야만** 통계적으로 감소(√N 반비례).

## 왜 필요한가 (현황)

| 항목 | 현재 |
|---|---|
| 어금니 학습 케이스(정상 12개) | 약 168건 |
| 어금니 길이오차(KRR) | 0.78mm (앞니 0.35mm의 2.2배) |
| 교정후 사진 소진 | 114장 중 108장 라벨 완료(정상 61 + 발치 47) |

**교정후 데이터는 거의 소진**됐고, 발치 47건은 어금니 학습에 못 씀(규칙 baseline 정렬 80% 이탈). 따라서 **교정후 폴더 밖의 정상배열 신규 사진**이 필요.

## 어떤 데이터가 필요한가

### 1) 케이스 조건 (필수)
- **발치하지 않은 정상 12개 치아 배열** (하악 교합면). 발치 케이스는 학습에서 자동 제외되므로 무효.
- **어금니(양측 최후방 1·2·11·12번)가 사진에 온전히 보이는** 것. 잘리거나 그림자로 가려지면 라벨 부정확.
- 기존 학습 케이스와 **다른 환자/다른 사진**(SHA 신규). 재보정(기존 재라벨)은 새 신호가 거의 없어 효과 미미.

### 2) 수량 목표
- 분산을 눈에 띄게 낮추려면 **정상배열 100건 이상 추가**(168 → 270+). 표본 √N 효과상 최소 이 정도라야 P95 꼬리가 내려감.
- 소량이라도 **어금니가 특히 어려운 케이스**(구치부 아치가 벌어진, 최후방이 안쪽으로 말린) 우선.

### 3) 라벨링 방법 (파이프라인 규격)
`보정 후 알고리즘 적용.html`에서:
1. 사진 업로드 → `⚡ 치아 자동 분석 실행`
2. `3. 치아 좌우폭 찍기`에서 **특히 어금니(1·2·11·12번) 좌우폭선을 드래그로 정밀 보정**
   - 자동예측(빨강)이 어금니에서 밀리므로, 실제 치아 경계에 맞게 끌어당길 것
   - 최후방 어금니 끝(1번·12번)이 가장 부정확하니 집중
3. `위치 저장(md)` 버튼 → md 저장 (imageData·toothWidths 12개·molarMm:54 포함)
4. **저장 폴더**: 신규 폴더 권장(예 `02 어금니 보강 라벨(김원장님)`), 파일명은 사진 번호 접두어

### 4) 제작 규칙 (⚠️ 정확도 직결)
- 크롭/회전/리사이즈 **금지** (SHA·스케일 깨짐)
- AI 예측 그대로 두지 말 것 — **반드시 눈으로 어금니 보정**
- 치아 번호 순서 통일(좌측 최후방 1 → 우측 최후방 12)
- 12개 미만이면(발치/결손) 어금니 학습엔 미사용 → 정상 12개 케이스 위주로

## 받은 후 실행 (자동)
1. SHA/좌표/번호/스케일 무결성 검사 (0byte·경계이탈 자동 플래그)
2. `build_dataset_index.mjs` 재빌드 → 신규 소스 편입
3. 규칙 baseline 생성 + `merge_baselines` → `train_residual` 재학습
4. **`analyze_molar_length.mjs`로 어금니 길이오차 전/후 비교** (현재 KRR 0.78mm 기준, 개선 확인)
5. 중첩 독립검증으로 TZL P95 게이트 재평가 → 개선 시 HTML 재임베드

## 참고: 재보정 우선순위(효과 낮음, 보조용)
기존 정답 케이스 중 어금니 오차 상위는 `molar_correction_targets.json`(rank_molar_error.mjs) 참조.
단 이미 학습된 케이스라 **재보정 효과는 신규 데이터보다 훨씬 작음**(라벨잡음 제거 수준).
